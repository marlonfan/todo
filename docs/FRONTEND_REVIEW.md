审查开始：2026-10-22。基线：`42ef297`。本报告记录本轮已确认问题、修复及验证，未提交、推送或发布。

## 目标与完成标准

检查架构、降低前端复杂模块的维护成本，修复可确认的流畅度和交互问题。完成标准是：下面已确认的行为问题均有修复和针对性验证；主要交互通过桌面、窄屏回归；架构建议区分已实施与后续建议；本地构建及前后端测试通过，并提供真实截图。视觉改动遵循先预览后提交的约定。

## 当前架构判断

- 后端的 handler / service / repository 分层总体清晰，本轮先检查其入口接线和运行验证，尚未进行完整的后端业务、安全审计。
- 前端离线写入采用本地存储、outbox 和同步引擎；这部分复杂性有明确业务原因，应保留离线和临时 ID 语义，避免为了减少文件数量而合并。
- 页面层承担过多相互独立的职责。基线 `TaskList.jsx` 6,033 行，包含任务投影、分组、选中、详情草稿、自动保存、重复规则、拖放、分屏和下拉刷新。`TaskModal.jsx` 2,615 行，`InfiniteCalendarCanvas.jsx` 2,179 行，`Settings.jsx` 2,004 行。行数只是定位线索，拆分应围绕职责及可验证的行为。
- 日历同时经过 Query、IndexedDB 和 Zustand。本轮统一了事件变更判断，并将缓存读取、分段请求、去重及失败保留收敛到 `calendarRangeLoader`，获取 Hook 负责订阅和生命周期。同步引擎与日历共用独立版本常量，避免启动代码引入日历加载实现。

## 已修复并验证

| 编号 | 问题与影响 | 修复与证据 |
| --- | --- | --- |
| F01 | `readTaskSplitRatio` 在首次访问、偏好缺失或损坏时将值钳制到 0.25，预期的 0.55 默认值失效；列表被迫落到布局下限。 | 区分无效值与有效值，默认恢复 55%；回归覆盖缺失、损坏、合法及越界值。 |
| F02 | 分屏偏好直接访问 localStorage，存储不可用时可能中断页面初始化或拖动提交。 | 读写异常降级为内存交互；存储抛错回归通过。 |
| F03 | 分屏每次 pointermove 都在 6,000 行页面中 setState，拖动成本随页面复杂度增加；失焦时缺少拖动结束处理。 | 将响应式布局、拖动、键盘和持久化集中到 `useTaskSplitLayout`，每帧只更新 CSS 变量，释放时提交状态；加入失焦清理、指针 ID 过滤，统一可持久化比例和实际宽度限制。浏览器验证拖动、重新加载、Home/方向键、窄屏和失焦。 |
| F04 | 日历未缓存日期返回新的空数组，不满足 Zustand 5 / React 外部存储快照需要稳定引用的要求。 | 复用冻结空数组；测试验证连续读取、无关日期更新及清空缓存后引用稳定。 |
| F05 | 日历签名和 Store 比较仅包含部分字段，忽略备注、地点等；仅改详情时会错误复用旧事件，字符串拼接也存在字段边界碰撞。 | 对完整 JSON 事件规范序列化，忽略对象键及事件次序，保留字段边界；Store 共用签名判断。单元回归覆盖详情字段、键顺序及分隔符碰撞；浏览器验证刷新周期后显示新的备注和地点。 |
| F06 | 任一日历分段刷新成功后，会连同失败段一起清除 stale/missing 标记；前台与预取共享请求时，部分消费者收不到结果。 | `calendarRangeLoader` 只暴露 load / refresh，仅移除成功段，失败段保持可重试，过期缓存继续展示；并发消费者共享 promise 且各自取得结果。7 项测试覆盖部分失败、重试、并发、缓存版本和本地存储失效。 |
| F07 | 任务行只能通过指针打开详情；完成状态按钮缺少明确操作名称。 | 标题使用原生 button，支持 Tab、Enter、Space 和可见焦点；状态按钮增加操作名称并独立处理。浏览器验证桌面打开详情、完成另一任务不切换详情，以及 375px 下空格打开弹窗。 |
| F08 | Service Worker 首次接管时无条件刷新，导致刚输入的注册信息被清空；多个刷新信号也增加重复刷新机会。 | 首次从无 controller 到被接管时保留页面，已有 worker 被替换时只刷新一次，以 controllerchange 为唯一信号。3 项生命周期测试和真实首次安装浏览器回归通过。SW 缓存版本更新至 v42。 |
| F09 | 已安装 react-hooks 插件，但未启用核心调用约束，后续重构易引入条件调用等错误。 | 先扫描确认现有代码无违反，再启用 `rules-of-hooks: error`；完整 lint 通过。 |

`TaskList.jsx` 从 6,033 行降至 5,917 行，分屏职责由 `useTaskSplitLayout` 承担；`useCalendarFetch.js` 从 427 行降至 163 行。任务草稿、保存及离线同步语义保留，并通过既有回归。

日历拖动测试修正了导航和断言缺陷：通过应用入口进入活动日历，避免操作默认页重定向期间的保留节点；使用服务端返回值的 epoch 比较时间，确保拖动确实改变开始时间且时长不变。读取坐标前等待布局稳定，避免初次缓存载入替换节点时取到空坐标；保留真实拖动和服务端结果断言，连续运行 5 轮均通过。

2. `TaskList.jsx` 和 `TaskModal.jsx` 重复实现了重复规则解析、选择回填及摘要，后续可整合共享的规则转换，并覆盖周/月/农历规则。
3. `InfiniteCalendarCanvas.jsx` 仍包含布局和多种手势状态。后续应按手势职责逐步拆分，在真实触摸设备上建立滚动、长按、拖动基准后再调整惯性参数。
